# 前端视觉与交互规范（强制）

## 核心判断

专业感 = **可预测的秩序 + 足够的信息 + 清晰层级 + 完整状态**。
不是更多渐变、动画或纹样。营销页可以有表现力；学习端与管理端必须克制、信息优先。

判断一个新样式是否合格，先回答三个问题：

1. 它是否帮助用户更快理解内容或完成任务？
2. 它是否复用了已有 token / 组件 / 布局原语？
3. 加载、空、错误、悬停、焦点、禁用状态下它是否仍然成立？

三个问题有一个答不上来，就不要写这段样式。

## 禁止事项

- 禁止使用没有定义的共享类名。新增或删除共享类名时，必须同步检查 `frontend/src` 内所有引用；`card-grid`、`tall-card` 曾因样式表被删而失效，卡片退化成整行横幅。
- 禁止在页面 scoped CSS 里写死颜色、圆角、阴影、间距；一律使用 `design-system.css` 的语义 token 或本 skill 定义的尺度。
- 禁止在应用内新增全局点击特效、常驻背景动画、无限循环动画；只保留反馈型动效（悬停、展开、加载、状态切换）。
- 禁止用假数据填充卡片元信息。字段不存在时先补 API，或宁可不展示。
- 禁止把同质条目硬做成大卡片；能列表就列表，卡片只用于“摘要 + 进入详情”。
- 禁止中文大标题使用明显负字距；中文正文与标题字距为 0。
- 禁止只做加载态。空、错误、无权限、提交中、禁用、悬停、焦点必须一起设计。
- 禁止为了“看起来高级”叠加玻璃拟态、发光边框、渐变文字、装饰性网格。
- 禁止在深色主题使用大面积棕色/橙色渐变、极光光斑、彩色毛玻璃；也不要把品牌色铺满 hero、卡片或整行（会变成脏灰、做旧照片感）。

## 设计令牌

所有页面共享 `frontend/src/styles/design-system.css` 的 token。新增 token 时同时定义 `:root` 与 `.dark`，并通过 `@theme inline` 暴露给 Tailwind。

### 颜色

使用语义名，不直接写十六进制：

- 表面：`background`（页面）→ `card`（输入框/表格/内嵌块等次级表面）→ `panel`（内容卡片与区块）→ `popover`（浮层）。浅色下页面用纯白 `background`，内容卡片用咖啡色 `panel` 与白色页面区分；深色下按此顺序逐级提亮。
- 文字：`foreground`（主，暖调近黑）、`muted-foreground`（次，暖灰；对咖啡色面板仍需 4.5:1 以上）。
- 强调：`primary` / `accent` / `accent-foreground`，只用于主动作、当前导航、关键数字。
- 状态：`destructive`（错误/危险）；其他状态优先复用 `accent` + 文案，不新增随机色。
- 分隔：`border` / `input`。

深色模式不要把 `background` 设成纯黑；完整约定见下方「深色模式」一节。

### 深色模式

深色模式是独立主题，不是把浅色反相。依据 Material 3 color roles、Apple HIG Dark Mode、IBM Carbon Gray 100、NN/g 与 WCAG 2.2 的共同做法：

- **表面中性**：大面积表面用中性石墨，不做棕色/橙色染色；RGB 通道极差 ≤ 4（`--panel` 允许 ±3 的暖度）。页面最暗、卡片与面板逐级提亮。
- **阶差要克制**：画布压到近黑（`--background: #050505` 一带，不用纯黑），页面到内容层 `ΔL*` 约 5–6；`card` / `panel` / `popover` 之间再各留 2–4。参考近黑仪表盘（Flux dashboard）的做法：整屏先读作黑色，卡片只靠一线边框浮现，而不是靠明显更亮的灰底。阶差再大，占屏近半的容器会反客为主，页面看起来是"黑底上摞灰板"。
- **边框只收边，不发光**：深色下边框亮度最多比卡体高一点点（`--border` 对 `--panel` ≈ 1.3:1）；边框一旦比卡片头带还亮，就成了卡内最显眼的元素，抢走标题的位置。浅色反之（边框比卡体略暗）。
- **层级靠明度 + 1px 边框**：卡片/面板用 `--border` 分隔，只有 popover/dialog 用 `--shadow-popover`；不要给卡片加彩色外发光、玻璃拟态或彩色阴影。
- **正文近白**：`--foreground` 取近中性白（如 `#fafaf9`，亮度 ≥ 0.94），次要文字用中性灰 `--muted-foreground`，对面板 ≥ 4.5:1。不要用 `opacity` 压暗正文，也不要在正文上加 `text-shadow`。
- **强调色只做小面积**：主按钮、链接、当前项、关键数字各一处即可。深色下强调色要提亮、降饱和（本项目铜色 `#d9a173`），禁止铺满 hero、卡片或整行作为背景。
- **禁止大面积光效**：业务页（学习端、管理端）不使用极光、光斑、噪点、彩色渐变、无限旋转/漂移动画；营销首页的装饰也必须静止或可被 `prefers-reduced-motion` 关闭，且不得覆盖文字区域。
- **图片与图标**：提供暗色版本或降低亮度；不要直接把白底截图/插画贴到深色面板上。
- **两套主题同权**：深色不是“能看就行”。新增组件必须同时在 `:root` 与 `.dark` 下验证，正文 4.5:1、大字/图形 3:1、焦点环 3:1。

参考：Material 3 color roles（surface container 层级）、Apple Human Interface Guidelines Dark Mode（base/elevated background、语义文字色）、IBM Carbon Gray 100（`#161616` 基色、层叠表面）、NN/g Dark Mode 研究（对比极性，不默认深色更优）、WCAG 2.2 1.4.3 / 1.4.11。

### 间距

4px 基准，只使用以下档位：

`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 64`

页面内边距 20–32px；卡片内边距 16–24px；区块间距 24–48px。不要出现 `0.45rem`、`1.1rem` 这类随手值。

### 字号与行高

只使用六档：

| Token | 用途 | 行高 |
|---|---|---|
| 12px | 辅助信息、标签、元数据 | 1.5 |
| 13px | 次要正文、说明 | 1.6 |
| 14px | 正文 | 1.6 |
| 16px | 卡片标题、表单正文 | 1.5 |
| 18px | 区块标题 | 1.4 |
| 22–26px | 页面标题 | 1.3 |
| 32px | 营销/空态大标题 | 1.2 |

正文最大行宽约 72 字符；中文长文行高 1.7。数字使用 `font-variant-numeric: tabular-nums`。

### 字体

- 正文：系统 UI 栈（`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", "Noto Sans SC", sans-serif`）。不要声明实际未加载的字体名。
- 代码/命令/分值/slug：`ui-monospace, "SFMono-Regular", Consolas, monospace`。
- 中文标题字距 0；只有大号拉丁标题允许 `-0.02em`。

### 圆角

- 控件/输入：8px
- 卡片：12px
- 弹层/大容器：14–16px
- 胶囊：999px

同一页面不要混用 6/8/10/12/16px。

## 布局原语

以下类名常驻 `design-system.css`，页面直接复用：

- `.page-head`：标题 + 副标题 + 右侧动作，flex 两端对齐，底部 24px。标题与副标题必须包在同一个 `<div>` 里；直接作为两个 flex 子项会被拆到左右两端。
- `.page-title`：22–26px / 600，`margin: 0`。
- `.page-sub`：13px，`muted-foreground`，最大宽度 680px。
- `.page-actions`：右对齐按钮组。
- `.card-grid`：自适应网格，`minmax(280px, 1fr)`。
- `.card-grid.topics`：固定 3 列（≤1100px 2 列，≤720px 1 列）。
- `.tall-card`：`height: 100%; display: flex; flex-direction: column;`，保证同排卡片底部对齐。

页面不应再自己定义同名布局类。

### 页面级 tab

- 统一使用 `<UiTabs>`，位置固定在 `.page-head` 之后、统计卡/筛选/表格之前；不要因为页面内容不同把 tab 条推到统计之后。
- 形态是页头下方的整宽下划线导航：active 使用 `primary` 2px 下划线 + `accent-foreground` 文字，与 `.admin-subnav` 同一语法。页面级导航不要用胶囊/分段控件。
- 跨 tab 共享的摘要（例如竞赛统计卡）放进 `<UiTabs>` 的 `#summary` 插槽，保证 tab 条始终位于摘要之前。
- 窄屏横向滚动，不换行、不缩小字号；tab label 保持单行。

## 页面配方

### 列表 / 网格页（学习路线、题库）

```text
page-head: 标题 + 一句说明 + 搜索/筛选/继续学习
tabs（可选）: 页面级下划线导航，位于统计/筛选之前
stats（可选）: 仅展示真实数据
card-grid: 3/2/1 列
每张卡: 身份/图标或序号 + 标题 + 两行摘要 + 2–4 个元信息 + 明确入口
states: skeleton 贴合最终布局；empty 带下一步动作；error 带重试
```

### 详情页

标题 + 关键元信息（难度、状态、更新时间）在首屏；正文最大宽度 72ch；主要操作固定在内容区上方或右侧，不要藏在滚动底部。

### 管理表格页

工具栏（搜索/筛选/主按钮）→ 表格 → 分页。表格行高一致，操作列不超过两个直接按钮，其余收进菜单。空表给“新建/导入”动作，错误给重试。

### 管理端预览页

管理端复用学生端内容视图时，标题要明确“预览”语境，并在页头提供直达「内容管理」的动作，不要求用户回顶栏再找入口。详情页用面包屑回列表；同一目标只保留一份导航，不要同时渲染“学习路线”和“具体专题”两套等价链接。

### 表单

标签在上，帮助文字在输入框下，错误信息紧贴字段；主按钮在右、次按钮在左；提交中禁用并显示进度；破坏性操作二次确认。

## 卡片规则

- 卡片必须承载摘要：标题、1–2 行说明、2–4 个真实元信息、一个明确入口。
- 同一组卡片的信息顺序一致，方便横向比较。
- 卡片高度一致；整卡可点击；CTA 不能只在 hover 时出现。
- 装饰面积不超过卡片高度的 15%；不要用无含义的 84px 纹样。
- 悬停只改变边框/背景/轻微位移；不要放大、发光、旋转。
- 焦点态必须可见：`a:focus-visible > .card` 显示 2px `ring`。
- 空卡片、同一模板硬套所有内容，是“模板感”的主要来源。

## 状态

每个数据页面都要显式实现：

- 加载：骨架屏结构与最终布局一致，不用一整块 spinner 代替。
- 空：说明为什么空 + 一个下一步动作。
- 错误：`role="alert"` + 可读原因 + 重试按钮，不要把错误伪装成空态。
- 无权限：说明需要什么角色/权限，不返回 404 掩盖。
- 提交中：禁用主按钮、保留上下文、避免重复提交。
- 悬停/焦点/按下/禁用：四态齐全。

## 动效

- 只用于反馈和空间关系：150–200ms，`ease-out`。
- 不做常驻、循环、跟随鼠标的装饰动画。
- 营销页动画限制在首屏，进入业务页即停止。
- 必须尊重 `prefers-reduced-motion`。

## 可访问性

- 正文对比度 ≥ 4.5:1；大字号 ≥ 3:1。
- 所有交互元素有可见焦点；键盘可完成主流程。
- 图标按钮有 `aria-label`；状态变化有 `role="status"` / `role="alert"`。
- 触控目标 ≥ 44px（移动端）。
- 不只用颜色表达状态（同时给文字/图标）。

## 响应式

至少检查 1440 / 1024 / 390 三个宽度：

- 1440：内容区最大宽度约 1280，3 列网格。
- 1024：2 列，顶栏低频入口收起。
- 390：1 列，无横向溢出，触控目标足够大。
- 卡片、表格、筛选条、弹窗都要在 390 下可用。

## 修改流程

1. 先读 `frontend/src/styles/design-system.css` 和目标页面，确认现有 token 与共享类。
2. 用 `grep` 检查准备新增/删除的类名在全仓库的引用；不允许留下死类名。
3. 先改布局原语和共享样式，再改单页；不要用页面 scoped CSS 覆盖系统问题。
4. 补 e2e 回归（布局类 bug 必须覆盖真实用户路径），先红后绿。视觉规范（配色、对比度、明度层级、字重）不写进 e2e 断言——按本 skill 的约定实现，用 1440/1024/390 截图人工检查；e2e 只断言用户可见的功能终态。
5. 跑 `npm run build`（含 vue-tsc）与相关 e2e；共享布局改动跑全量 e2e。
6. 截图检查 1440/1024/390；做一次“眯眼测试”，确认层级仍然清楚。

## 审查清单

- [ ] 页面标题、副标题、主要动作在首屏一眼可见。
- [ ] 没有未定义的共享类名；没有硬编码颜色/圆角/间距。
- [ ] 卡片信息足够，装饰面积克制，CTA 常显。
- [ ] 加载、空、错误、无权限、提交中都有状态。
- [ ] 悬停、焦点、按下、禁用四态齐全。
- [ ] 中文排版字距正常；数字等宽。
- [ ] 1440/1024/390 无溢出、无整行大卡片。
- [ ] 没有新增常驻动画/全局点击特效。
- [ ] 深色表面为中性石墨，层级靠明度与边框，不靠光晕；品牌色没有铺满大面积。
- [ ] 深色正文/次要文字/焦点环对比度达标，且没有用 opacity 压暗正文。
- [ ] `npm run build` 与相关 e2e 全绿。

## 反例

❌ 为了“高级感”加渐变文字、发光边框、玻璃卡片。
❌ 卡片顶部放 84px 纯装饰纹样，标题和元信息却很少。
❌ 直接写 `#ff8c54`、`border-radius: 10px`、`gap: 0.45rem`。
❌ 删除旧样式表后不检查类名引用，留下 `card-grid` 这种空壳。
❌ 加载失败时显示“暂无内容”，用户以为没有数据。
❌ 只在 hover 时显示“进入”，键盘和触屏用户看不到入口。
❌ 深色模式整页深棕，每块面板再叠一层暖色渐变，像做旧照片。
❌ 业务页 hero 铺 40% 不透明度的品牌色光斑再 blur 56px，文字可读但整块区域发浑。
❌ 深色下用纯黑背景 + 纯白粗体小字，或把正文调到 `opacity: .7`。
