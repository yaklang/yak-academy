# 前端视觉与交互规范（强制）

完整设计见 `docs/frontend-design.md`（权威源）。本文件是执行摘要，冲突时以文档为准。

## 核心判断

专业感 = **可预测的秩序 + 足够的信息 + 清晰层级 + 完整状态**。不是更多渐变、动画或纹样。
营销页可以有表现力；学习端与管理端必须克制、信息优先。写任何样式前先回答：

1. 它是否帮助用户更快理解内容或完成任务？
2. 它是否复用了已有 token / 组件 / 布局原语？
3. 加载、空、错误、悬停、焦点、禁用状态下它是否仍然成立？

有一个答不上来，就不要写这段样式。

## 视觉基调

- **中性专业**：浅色白/浅灰画布 + 白色内容面 + 浅灰侧栏；深色中性石墨，不用纯黑。
- **品牌橙只做强调**：主操作、当前项、关键数值、焦点环；禁止铺满 hero/卡片/整行。
- **结构与主题解耦**：深浅色共用同一组件树，只切换语义 token。
- **列表优先**：能表格就表格，卡片只承载“摘要 + 入口”。

## 禁止事项

- 禁止 token 文件外写死颜色、圆角、阴影、间距；禁止 `!important` 与静态内联 style。
- 禁止未定义的共享类名；新增/删除类名必须 `grep` 全仓库引用。
- 禁止常驻/循环/跟随鼠标的装饰动画；只保留反馈型动效。
- 禁止假数据填充；字段不存在先补 API，或宁可不展示。
- 禁止 page 内再套 panel + table 双层卡片；禁止同质条目硬做大卡片。
- 禁止玻璃拟态、发光边框、渐变文字、装饰性网格、大面积暖米色/咖啡色表面。
- 禁止只做加载态；空、错误、无权限、提交中、禁用、悬停、焦点必须一起设计。
- 禁止页面手写 `.page-head`、筛选条、KPI 条、表格卡片；用共享原语。

## 设计令牌

所有页面共享 `frontend/src/styles/tokens.css`（语义层）与 `design-system.css`（聚合入口）。
新增 token 同时定义浅/深两套，并通过 `@theme inline` 暴露给 Tailwind。

### 颜色（只引用语义名）

表面：`--bg-canvas` → `--bg-surface` → `--bg-surface-raised`；`--bg-subtle/hover/active`。
文字：`--text-primary` / `--text-secondary` / `--text-tertiary`。
强调：`--action-primary(-hover/-fg)` / `--action-subtle(-fg)`；焦点 `--focus-ring`。
状态：`--status-success/warning/danger/info`；图表 `--chart-1…5`。
兼容层把 shadcn 的 `--background/--card/--primary/...` 映射到语义层，页面不得新增颜色变量。

深色：大面积表面中性（RGB 极差 ≤4），层级靠明度 + 1px 边框，不用彩色外发光；
正文近白，次要文字中性灰且对面板 ≥4.5:1；强调色只做小面积。

### 间距

只用 `4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 64`。页面外边距 16（≤720 用 12），
卡片内边距 12/16。不出现 `0.45rem`、`1.1rem` 这类随手值。

### 字号（只允许角色表）

| 角色 | 字号/字重 | 用途 |
|---|---|---|
| 微型 | 11 / 500 | 徽标、计数 |
| 元数据 | 12 / 400 | 表格元信息、时间 |
| 表头 | 12 / 500 | 表头、字段标签 |
| 次要 | 13 / 400 | 次要正文、帮助 |
| 正文 | 14 / 400 | 默认正文 |
| 区块标题 | 16 / 600 | 卡片/区块标题 |
| 页面标题 | 20 / 600 | 每页唯一 `h1` |
| 指标 | 24 / 600 | StatCard 数值 |
| 展示 | 32 / 600 | 公开页 hero |

不出现 9/10/15/19/21/28/30/44/110/120px；不用 `clamp()` 字号；中文标题字距 0；
数字 `font-variant-numeric: tabular-nums`；正文最大 72ch。

### 字体

系统 sans 栈 + 现有 mono；不声明未加载字体（删除 `components.json` 的 `geist-sans`）。

### 圆角

`--radius-control: 8` / `--radius-card: 12` / `--radius-overlay: 16` / `--radius-pill: 999`。
Tailwind `--radius-sm/md/lg/xl` 显式映射 6/8/10/12，不再 `calc(var(--radius) * …)`。

### 阴影与宽度

阴影只给 popover/dialog/drawer；卡片靠边框与明度差。
应用内容最大 1280；公开页 1200–1280；竞赛满屏 1440。外壳：48px 图标栏 + 224px 菜单 + 48px 顶栏。

## 布局原语

必须复用（详见 `frontend/src/components/layout` 与 `frontend/src/components/system`）：

- `AppShell` / `SidebarNav` / `TopBar`：唯一外壳；页面不再写 header。
- `PageHeader`：唯一 `h1`、描述、面包屑、右侧动作、可选页内 tabs。
- `PageTabs`：管理端分组切换，替代第二条 subnav。
- `DataTablePanel`：标题/计数/工具栏/表格/分页一体；列表页唯一容器。
- `EmptyState`：首次空 / 筛选空 / 错误三态 + 下一步。
- `StatCard` / `MetricStrip`：统一 KPI 条。
- `StatusTag`：状态/难度/角色中文映射 + tone。
- `FilterBar` / `Toolbar`：搜索、筛选、清除、主操作。
- `FormSection` / `FormField`：标签、帮助、错误、aria 绑定。
- `ConfirmDialog`：破坏性操作二次确认。
- `UiTable`：横向滚动、sticky 表头、`aria-sort`、行键盘激活、动态选择标签。

## 页面配方

- **列表/管理页**：`PageHeader` → `DataTablePanel`；1440×900 至少 5 行；1024/390 不裁切。
- **详情/阅读页**：`PageHeader` → 72ch 正文列 + 右侧操作栏（≥1024）；<1024 单列。
- **表单/设置页**：`PageHeader` → `FormSection`；主按钮右下，错误贴字段。
- **满屏页**（竞赛入场/首页）：独立 `CompetitionShell`，复用 token/表格/状态。
- **公开页**（Landing/Login）：静态品牌视觉 + 清晰 CTA，不进入应用外壳。

## 卡片规则

- 卡片必须承载摘要：标题、1–2 行说明、2–4 个真实元信息、一个明确入口。
- 同组卡片信息顺序一致；高度一致；整卡可点击；CTA 不能只在 hover 出现。
- 装饰面积不超过卡片高度 15%；悬停只改边框/背景/轻微位移，不放大、不发光、不旋转。
- 焦点态必须可见：`a:focus-visible > .card` 显示 2px `ring`。

## 状态

每个数据页面显式实现：

- 加载：骨架结构与最终布局一致，不用一整块 spinner 代替。
- 空：说明为什么空 + 一个下一步动作；筛选空给“清除筛选”。
- 错误：`role="alert"` + 可读原因 + 重试，不把错误伪装成空态。
- 无权限：说明需要什么角色/权限，不返回 404 掩盖。
- 提交中：禁用主按钮、保留上下文、避免重复提交。
- 悬停/焦点/按下/禁用：四态齐全。

## 文案

界面不得出现 `running/draft/published/archived`、`ACADEMY_*`、`flag_mode`、`noop`、`slug`、原始 JSON。
统一术语：Room→“章节”、WP→“解题报告”、“普通人”→“学员”、“账号 ID”→“账号编码”；
状态/难度/角色全部走 `lib/format` 的中文映射表。

## 动效

只用于反馈和空间关系：120–200ms，`ease-out`；尊重 `prefers-reduced-motion`。
禁止常驻、循环、跟随鼠标的装饰动画；公开页动画也必须静止或可关闭。

## 可访问性

- 每页恰好一个 `h1`；表格 caption/`aria-label`；可排序列 `aria-sort`；行可键盘激活。
- 正文对比 ≥4.5:1，大字/图形 ≥3:1；焦点环 2px 可见。
- 图标按钮有 `aria-label`；状态变化有 `role="status"`/`role="alert"`。
- 移动端触控目标 ≥44px；不只用颜色表达状态。

## 响应式

至少检查 1440 / 1024 / 390：

- 1440：内容最大 1280，表格完整，≥5 行。
- 1024：侧栏可折叠，筛选分级收纳，表格横向滚动可用。
- 390：单列，无横向溢出，触控目标足够，操作列可达。

## 修改流程

1. 先读 `docs/frontend-design.md`、`frontend/src/styles/tokens.css` 和目标页面。
2. `grep` 检查准备新增/删除的类名在全仓库的引用；不留死类名。
3. 先改原语与共享样式，再改单页；不用页面 scoped CSS 覆盖系统问题。
4. 补 e2e 回归（布局类 bug 必须覆盖真实用户路径），先红后绿；
   结构/可读性契约（无横向溢出、单一 h1、角色字号、对比度、44px 触控目标）
   由 `frontend/e2e/visual-qa.spec.ts` 自动守护；配色与明度层级的具体观感
   仍按 1440/1024/390 截图人工复核，不做像素基线。
5. 跑 `npm run check:design && npm run check:census && npm run check:copy && npm run build && npm test`，共享布局改动跑全量 e2e。
6. 截图检查 1440/1024/390；做一次“眯眼测试”，确认层级仍然清楚。

## 审查清单

- [ ] 页面标题、描述、主操作首屏可见。
- [ ] 没有未定义类名；没有 token 文件外的硬编码颜色/圆角/间距；无 `!important`。
- [ ] 列表页使用 `DataTablePanel`，1440×900 至少 5 行，1024/390 不裁切。
- [ ] 卡片信息足够，装饰克制，CTA 常显。
- [ ] 加载、空、错误、无权限、提交中都有状态，空态有下一步。
- [ ] 悬停、焦点、按下、禁用四态齐全。
- [ ] 每页一个 `h1`；表格/表单 aria 完整；对比度达标。
- [ ] 界面无内部术语与裸枚举。
- [ ] 1440/1024/390 无溢出、无整行大卡片。
- [ ] 无新增常驻动画/全局点击特效。
- [ ] 深色为中性石墨，品牌色没有铺满大面积。
- [ ] `check:design`、`check:census`、`check:copy`、`build`、`test`、相关 e2e 全绿。

## 反例

❌ 为了“高级感”加渐变文字、发光边框、玻璃卡片。
❌ 卡片顶部放 84px 纯装饰纹样，标题和元信息却很少。
❌ 直接写 `#ff8c54`、`border-radius: 10px`、`gap: 0.45rem`。
❌ 删除旧样式表后不检查类名引用，留下 `card-grid` 这种空壳。
❌ 加载失败时显示“暂无内容”，用户以为没有数据。
❌ 只在 hover 时显示“进入”，键盘和触屏用户看不到入口。
❌ 深色模式整页深棕，每块面板再叠一层暖色渐变，像做旧照片。
❌ 业务页 hero 铺 40% 不透明度的品牌色光斑再 blur，文字可读但整块区域发浑。
❌ 表格列宽硬编码总和超过容器，又被 `overflow-hidden` 裁切。
