# 两档角色模型（强制）

## 全局角色（仅两档）

| 值 | 中文 | 能力 |
|---|---|---|
| `student` | 普通人 | 浏览教程/训练场、提交答案、进度与排行榜；**不显示管理端入口** |
| `admin` | 管理员 | 管理端全部能力（内容包、题目、容器、用户） |

- **禁止**再引入 `teacher` 或课程级角色参与鉴权。历史 `teacher` 启动迁移降为 `student`。
- 权限判定只看全局 `Rank`：`admin` 短路通过全部管理接口；普通人访问管理接口 → 403。

## 接口鉴权规则（强制）

- **每个接口必须声明所需角色**（路由注册时的声明式元数据），由统一中间件执行。
- **禁止**在 handler 函数体内写 `if user.Role == ...` 这类散落权限判断。
- 资源属主判断放 service 层，角色/权限检查放中间件。
- **公开接口仅两个**：`POST /auth/login`（JWT 换取）与 `POST /checkpoints/{token}`（环境检测点回调，token 即能力凭证——每实例随机生成、注入容器、实例销毁即失效；无 JWT 语义，不适用角色判定）。新增公开接口必须先在 architecture.md 立项。

## 接口 → 最低角色速查

| 操作 | 最低角色 |
|---|---|
| 浏览已发布教程与训练场、提交答案、查看自己进度、徽章 | student（登录即可） |
| 环境检测点回调（容器内 checker） | 公开（checkpoint token 鉴权） |
| 上传/发布教程包、题目管理、容器、用户 | admin |

- 鉴权失败统一返回 403 + 错误码（见 api-contract skill），**禁止**返回 404 掩盖权限问题。

## 前端约束

- 普通人布局**禁止**渲染「进入管理端」链接。
- `/admin/*` 路由守卫仅放行 `global_role === 'admin'`。

## 正反例

✅ 正确：`POST /content/packages` 注册时声明 `"admin"`。
✅ 正确：普通人导航只有教程 / 训练，无管理入口。
❌ 错误：给 student 显示管理端入口再靠接口 403。
❌ 错误：恢复 teacher 或课程级角色参与鉴权。
