# 闭合技巧：模糊查询点上的精确统计

## 原理背景

上一课的数字型注入不需要闭合任何东西，但真实业务的注入点常常被"包装"起来：

```sql
select * from vulin_users where (username LIKE '%<输入>%') and (age > 20)
```

你的输入被夹在 `'%` 和 `%'` 之间，后面还有整段附加条件。注入 payload 必须：

1. **闭合**左侧的引号与百分号（`a%'`）；
2. 注入 UNION 查询；
3. **注释掉**尾部的 `') and (age > 20)`（`--` 后跟空格）。

这层"拆包装纸"的功夫，是手工注入从入门到进阶的分水岭。

## Yakit 操作步骤

本课的核心是**批量试错**——闭合类 payload 一两个字符错了整条就废，逐个手发效率太低：

1. Web Fuzzer 里把注入点参数化：`?name={{payload}}`；
2. 准备一组候选 payload（不同闭合组合、不同列数对齐）作为字典；
3. 一次执行，右侧并排展示每个 payload 的响应，快速定位"哪个 payload 活了"；
4. 特殊字符（`%`、引号、括号、空格）在 URL 里需要编码——payload 整体过一遍 **Codec 的 URL 编码**，或直接让 Fuzzer 自动编码。

## 开始实战

点击 **前往配套题目练习**，启动环境后：

1. 观察 `/user/name/like?name=a` 的正常响应，确认注入点被 `'%...%'` 包裹、尾部还有 `(age > 20)`；
2. 构造 `name=a%') UNION SELECT ...-- ` 形态的 payload（URL 编码后发送）：
   - 先用 `UNION SELECT NULL,...` 对齐列数；
   - 再换成统计查询（题目要求的是 `vulin_users` 表的**用户总数**，靶场每次启动会生成随机账号，数字必须现场注入统计）；
3. 响应里的数字即答案。注意 `--` 后面留一个空格才能吞掉后面的条件。

## 延伸：fuzztag 进阶

Web Fuzzer 的 fuzztag 家族还有 `{{int(1,20)}}`（数字区间）、`{{base64(...)}}`（边发边编码）、`{{randstr(8)}}`（随机串）等。把"探测列数"做成 `ORDER BY {{int(1,10)}}` 的一次执行，就是最典型的用法——这种"参数化一切"的思维，是从手工测试走向自动化测试的第一步。
