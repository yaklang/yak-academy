# SSRF 初探：让服务器替你访问内网

## 原理背景

**SSRF（服务端请求伪造）**：应用提供了"用户给 URL、服务端去请求"的功能，却没校验目标地址。攻击者把 URL 指向**内网**或**服务自身**，就能借服务器的手访问浏览器根本到不了的地方——读云元数据、探内网端口、访问只对 localhost 放行的管理接口。

本课靶场正是第三种：`/ssrf/flag` 只信任"来自本机"的请求，而 `/ssrf/in-get` 恰好愿意替任何用户请求任意 URL。

## Yakit 操作步骤

1. Web Fuzzer 构造 `GET /ssrf/in-get?url=<目标>` 请求发送，先用一个普通外网地址观察"代理请求"的行为（响应里回显了目标页面内容）；
2. 换成指向靶机自身的内网地址（`http://127.0.0.1:8787/...`）——从你的浏览器直连这个地址会被拒绝，但经 SSRF 一跳，请求的发起方成了服务器自己；
3. 需要传特殊字符的 URL 时用 **Codec 的 URL 编码** 处理参数。

## 开始实战

点击 **前往配套题目练习**，启动环境后：

1. 浏览器直连 `/ssrf/flag` 感受被拒（它只对本机请求放行）；
2. 在 Web Fuzzer 里让 `/ssrf/in-get` 替你请求 `http://127.0.0.1:8787/ssrf/flag`（注意端口是 8787）；
3. 响应里的 `flag{uuid}` 即答案（判定为正则匹配，uuid 原样提交）。

环境首页是靶场的路由索引页，先逛一圈能对全部靶机入口有个地图。

## 延伸：盲 SSRF 与反连平台

很多 SSRF **没有回显**（请求发出去了，响应看不到），这时要靠 **综合反连 OOB**：把 URL 指向 Yakit 反连平台分配给你的回调域名，目标服务器一旦发起请求，平台立刻记录下来——"它确实访问了"本身就是漏洞证据。反连是验证无回显 RCE、盲 SSRF、盲 XXE 的通用手段，值得单独深入。
