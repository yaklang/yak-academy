# SSRF 初探：让服务器替你访问内网

## 原理背景

**SSRF（服务端请求伪造）**：应用提供了"用户给 URL、服务端去请求"的功能，却没校验目标地址。攻击者把 URL 指向**内网**或**服务自身**，就能借服务器的手访问浏览器根本到不了的地方——读云元数据、探内网端口、访问只对"自己"放行的管理接口。

本课靶场正是第三种：`/ssrf/flag` 只对"像是发给靶机本机"的请求放行，而 `/ssrf/in-get` 恰好愿意替任何用户请求任意 URL。它的"本机检查"实现得非常直白——只看请求的 **Host 头里是否包含 `127.0.0.1`**：用 `localhost` 域名直连会被拒（Host 不含 `127.0.0.1`，返回 500）；而经 SSRF 一跳，请求由靶机自己发给 `127.0.0.1:8787`，Host 天然满足条件。这种"靠自我声明"的检查本身就是个反面教材——真实系统里对应的是"只信任内网来源"的接口被 SSRF 借道打穿。

## Yakit 操作步骤

1. Web Fuzzer 构造 `GET /ssrf/in-get?url=<目标>` 请求发送（`Host` 头只写 `主机:端口`），先用一个普通外网地址观察"代理请求"的行为——响应是**原样转发的目标响应原文**（状态行、响应头、body 一起回来）；
2. 换成指向靶机自身的内网地址（`http://127.0.0.1:8787/...`）——从你的浏览器直连 `localhost` 版本会被拒绝，但经 SSRF 一跳，请求的发起方成了服务器自己；
3. 需要传特殊字符的 URL 时用 **Codec 的 URL 编码** 处理参数。

## 开始实战

点击 **前往配套题目练习**，启动环境后：

1. 浏览器先用 `localhost` 直连 `http://localhost:<端口>/ssrf/flag` 感受被拒（500）；
2. 在 Web Fuzzer 里让 `/ssrf/in-get` 替你请求 `http://127.0.0.1:8787/ssrf/flag`（注意端口是 8787）；
3. 响应原文的 HTML 里就有 `flag{uuid}`——每次请求都会生成新的 uuid，判定为正则匹配，把你拿到的那个原样提交即可。

**第 1 步：启动实验环境**

题目详情页点「启动实验环境」，等状态 running，复制访问地址（形如 `http://127.0.0.1:36870`）。

**第 2 步（可选）：用 localhost 直连，体会被拒**

浏览器访问 `http://localhost:36870/ssrf/flag`（注意这里用 `localhost` 域名而不是 `127.0.0.1`），得到 **500**——因为 Host 头是 `localhost:36870`，不含 `127.0.0.1`。

> 靶场的检查只看 Host 字符串：如果你直接用 `http://127.0.0.1:36870/ssrf/flag` 访问，Host 含 `127.0.0.1`，同样能通过——这恰恰说明"自我识别"式校验有多脆弱。真实世界的对应场景：管理接口只允许内网访问，攻击者借 SSRF 让服务器"自己访问自己"。

**第 3 步：观察 /ssrf/in-get 的代理行为**

在 Web Fuzzer 发送：

```http
GET /ssrf/in-get?url=http://www.baidu.com HTTP/1.1
Host: 127.0.0.1:36870
```

响应是 baidu 页面的**完整响应原文**（第一行 `HTTP/1.1 200 OK`，接着响应头，然后 HTML）——确认这个接口是"服务端替你请求，再把结果原样搬回来"。

**第 4 步：SSRF 一跳，让靶机自己请求 /ssrf/flag**

```http
GET /ssrf/in-get?url=http://127.0.0.1:8787/ssrf/flag HTTP/1.1
Host: 127.0.0.1:36870
```

两个端口的分工：`36870` 是映射到你本机的实例端口（Host 头写它），`8787` 是靶场服务在容器内部监听的端口（被请求的内网地址写它）。响应原文是一个 "Example DEMO" 页面，拉到 body 末尾：

```html
<div>
	flag{9bbdcff2-8ca0-4ff1-ae4b-56ff40e4f02f}
</div>
```

`flag{}` 里是你的 uuid（每次请求都不同，属正常现象）。

**第 5 步：提交答案**

回到题目详情页，提交你拿到的完整 `flag{uuid}` 原文。

## 延伸：盲 SSRF 与反连平台

很多 SSRF **没有回显**（请求发出去了，响应看不到），这时要靠 **综合反连 OOB**：把 URL 指向 Yakit 反连平台分配给你的回调域名，目标服务器一旦发起请求，平台立刻记录下来——"它确实访问了"本身就是漏洞证据。反连是验证无回显 RCE、盲 SSRF、盲 XXE 的通用手段，值得单独深入。
