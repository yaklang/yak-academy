# MITM 会话链：先代理观察，再复用会话

## 原理背景

Web Fuzzer 是"从零手搓"，MITM 的方法论正好相反：**先让真实业务流量跑起来，你在旁边看**。浏览器登录、下单、查资料——每一步都从代理里过，MITM 历史把它们全部落库。这时你手里的不再是想象的请求，而是**带真实会话态的请求原文**。

会话（Cookie）是这条链的灵魂：登录响应 `Set-Cookie` 签发会话，后续请求靠它保持登录态。测试越权、测试会话固定、测试接口鉴权，套路都是同一个——**在代理观察到的流量里，找到那个携带会话的请求，改掉身份相关字段重放**。

> 一个经典陷阱：靶场**商城**（mall 模块）的登录接口永远下发固定值 `sessionID=fixedSessionID`——那是会话固定漏洞的产物，抓一百次都同一个值，毫无"观察"价值。真正像真实系统的是 **logic 模块**的登录：每次登录动态签发一个 uuid 会话（`_cookie`）。本题只认动态签发的会话——在代理流量里分辨"哪个是活会话、哪个是摆设"，正是 MITM 观察力的考点。

## Yakit 操作步骤

1. **配代理**：系统（或浏览器插件）代理指向 Yakit MITM 监听地址，装一次证书（MITM 页有引导）；
2. **真实登录**：浏览器里用 `user1` / `password123` 登录靶场的 logic 模块——登录请求、`Set-Cookie` 响应全部出现在 MITM 历史；
3. **观察会话**：登录后的受保护请求自动携带 `_cookie`——在历史里点开一条，看请求头里的会话值与登录响应签发值是否一致；
4. **复用改包**：右键历史请求「发送到 Web Fuzzer」，改掉想改的字段重放——会话原样携带，服务端视角与你本人在操作无异。

## 开始实战

点击 **前往配套题目练习**，启动环境后完成**两步链**：

1. 请求 `POST /logic/user/login`（JSON：账号 `user1` / 密码 `password123`）——响应 `Set-Cookie` 签发**动态** `_cookie` 会话 uuid（响应 JSON 里的 `id: 3` 是你的用户 id，下一步要用）；
2. 携带这个**动态**会话请求 `GET /logic/user/profile?id=3`，响应渲染出你本人（user1）的资料即链路打通。

两步都被观察到后（预置的 `fixedSessionID` 不算——本题要的是动态签发的会话），`/flag` 端点解锁。读出本实例 flag 并提交，完成本题。

**第 1 步：启动实验环境**

题目详情页点「启动实验环境」，等状态 running，复制访问地址。

**第 2 步：真实登录，拿动态会话**

挂好 MITM 代理后在浏览器登录；不用浏览器的话，在 Web Fuzzer 发（与走代理是同一条链，网关都能观察到）：

```http
POST /logic/user/login HTTP/1.1
Host: 127.0.0.1:36870
Content-Type: application/json

{"username": "user1", "password": "password123"}
```

响应体 `{"id":3,"success":true,"message":"Login successful"}`——`id:3` 记下来；响应头 `Set-Cookie: _cookie=<动态 uuid>`——**记下这个值**，它只属于本次登录，数据库里没有任何预置副本。

**第 3 步：携带动态会话访问资料接口**

```http
GET /logic/user/profile?id=3 HTTP/1.1
Host: 127.0.0.1:36870
Cookie: _cookie=<第 2 步签发的动态 uuid>
```

响应渲染出 user1 的 User Profile（用户名、角色等字段）——动态会话复用成功。对照：不带 Cookie 发同一请求只会得到 `alert("请先登录")`。

**第 4 步：读取本实例 flag**

两步链（动态登录 → 动态会话复用）都被观察到后，`GET /flag` 自动解锁（之前直接访问是 403）：

```http
GET /flag HTTP/1.1
Host: 127.0.0.1:36870
```

响应就是 flag 原文（一行，`flag{lab-...}`）。

**第 5 步：提交答案**

回到题目详情页，在答案框输入刚读到的 flag 原文（`flag{lab-...}` 整串）提交。

## 延伸：代理观察是测试的起点

安全测试的标准开局不是打开扫描器，而是**挂代理把核心业务流程走一遍**：登录 → 下单 → 改资料 → 退出。MITM 历史里沉淀下来的，就是一套带会话态的真实请求样本库——后续所有手搓、重放、批量验证都从这份样本出发。配合热加载（用 Yak 脚本在 MITM 里自动改写流量），"观察 → 改写 → 验证"可以完全自动化，这正是 Yakit 代理链相对纯手搓工具的杀手锏。
